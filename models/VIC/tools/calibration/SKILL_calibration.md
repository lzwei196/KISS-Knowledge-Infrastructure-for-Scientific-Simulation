# VIC模型AI人工批次率定指南（强约束版）

## 适用范围
- 基于VIC + Routing进行流域日流量率定。
- 仅使用AI阶段，不使用随机探索阶段。
- 适用于用户指定初始土壤参数文件后，按批次人工决策迭代优化。

---

## 核心原则（必须遵守）

### 1) 控制权（写死）
- AI阶段参数必须由助手基于历史模拟结果和参数物理含义**人工分析后给出**。
- 不得调用脚本内自动决策函数（如 `ai_decide_params`、`decide_next_params` 或等价自动策略）。

### 2) 批次规则（写死）
- 每10次为1个批次。
- 流程固定为：
  1. 运行当前批次10组参数；
  2. 对本批次和全局历史进行分析；
  3. 产出下一批10组参数。
- 禁止一次性预生成全部100组参数。

### 3) 起始方式（写死）
- 不执行阶段一随机探索。
- 必须由用户指定初始土壤参数文件（或等价初始参数集）后，直接进入AI批次率定。

### 4) 自动执行边界（默认自动）
- 默认模式：`AUTO_CONTINUE=true`。
- 进入率定后，Agent应自动连续执行所有批次，直到触发停止条件。
- 不要求用户每批输入“继续下一批”。
- 仅当用户明确要求暂停/停止/修改策略时中断自动执行。

> 说明：若需要手动批次控制，可显式设置 `AUTO_CONTINUE=false`，此时“继续下一批”仅执行下一批10次。

---

## 率定参数与范围

| 参数 | 列索引 | 范围 | 说明 |
|---|---:|---|---|
| binfilt | 4 | 0.01–1.0 | 入渗曲线参数，影响洪峰与产流分配 |
| Ds | 5 | 0–1.0 | 非线性基流比例系数 |
| Dsmax | 6 | 5–20 | 最大基流速率 |
| Ws | 7 | 0.1–1.0 | 基流启动相对含水阈值 |
| soil_d2 | 23 | 0.3–1.0 | 第二层土壤厚度 |
| soil_d3 | 24 | 0.8–2.0 | 第三层土壤厚度 |

约束：
- `soil_d3 > soil_d2`
- 全参数必须在范围内
- 组合需满足物理合理性

---

## 停止条件（写死）
满足任一条件即停止：
1. `NSE > 0.85` 且最近连续10次结果满足 `|NSE(i)-NSE(i-1)| < 0.005`。
2. 达到用户指定率定次数（默认100次）。

说明：
- 连续10次变化判据以“相邻两次有效运行的NSE绝对差”计算。
- 若某次运行失败，该次不计入连续变化序列。

---

## 目录与命名规则（写死）

### 输出目录
- 输出目录名固定：`{流域名}_calibration_ai`
- 流域名来自对应shp文件（或其确定后的流域标识）

### 结果目录必须包含
- `best_run/`（全局最优参数对应的完整运行结果）
- `current_run/`（当前正在运行的一次结果）
- `calibration_results.csv`
- `calibration_log.txt`
- `batch_plan.md`
- `ai_analysis.md`
- `best_params.json`
- `manual_batch_plan.md`

---

## 结果文件格式说明（必须遵守）

### 1) calibration_results.csv
- 一次运行一行，推荐列：
- `run_id,phase,binfilt,Ds,Dsmax,Ws,soil_d2,soil_d3,NSE,RMSE,PBIAS,peak_ratio,lowflow_ratio`
- `phase` 建议值：`ai_manual`、`ai_manual2`... 或统一 `ai_manual`。

### 2) best_params.json
建议结构：
```json
{
  "run_id": 57,
  "params": {
    "binfilt": 0.218,
    "Ds": 0.0,
    "Dsmax": 6.3,
    "Ws": 0.585,
    "soil_d2": 0.342,
    "soil_d3": 0.82
  },
  "NSE": 0.8410,
  "RMSE": 558.71,
  "PBIAS": 7.49,
  "peak_ratio": 0.95,
  "lowflow_ratio": 4.65
}
```

### 3) batch_plan.md
- 记录“系统/流程生成”的批次计划（每批10组）。
- 每条包含：批次起始run、候选编号、6个参数值。

### 4) manual_batch_plan.md
- 记录“助手人工分析后给出的批次参数”。
- 每批必须有标题行，说明本批优化策略。
- 每条参数建议必须可追溯到具体 run_id。

### 5) ai_analysis.md
- 建议按 run 记录分析，至少包含：
- 当前结果（参数+指标）
- 本批最优对比
- 全局最优对比
- 下一批策略建议

### 6) calibration_log.txt
- 必须记录每次运行开始与结束时间，以及单次耗时。
- 日志格式：
```text
Run 57 start_time: 2026-02-06 21:12:03 | phase=ai_manual | params={...}
Run 57 end_time:   2026-02-06 21:14:11 | duration_sec=128.0 | NSE=0.8410 | RMSE=558.71 | PBIAS=7.49%
```
- 若失败需记录错误信息及失败时间。

---

## 每批输出要求（写死）
每完成1批（10次）必须输出并写入日志/分析文件：
1. 10组参数表（本批实际执行参数）
2. 本批Top结果（至少Top1，建议Top3）
3. 全局最优变化（是否刷新、刷新到多少）
4. 下一批建议方向（参数增减方向与原因）

建议同时写入：
- `calibration_log.txt`（简版）
- `ai_analysis.md`（详版）

---

## 推荐执行流程（默认自动）
1. 解析流域名，创建 `{流域名}_calibration_ai` 目录结构。
2. 读取用户指定初始土壤参数文件，生成 `Run 1`。
3. 按10次一批循环：
   - 人工分析 → 生成10组参数 → 逐次运行写结果。
4. 每批结束后输出批次总结，并自动进入下一批。
5. 满足停止条件后结束，保留 `best_run/` 与完整结果文件。

---

## 首次接入执行剧本（强制）
当Agent首次读取本skill时，必须按以下固定剧本执行，禁止改写流程：

### A. 批次开始固定话术（必须）
- 先输出一句：  
  `继续下一批。我会按“<本批策略名>”生成第N批10组参数（Run X-Y），并立即执行。`

### B. 批次执行方式（必须）
- 使用 `run_once` 逐次执行10组参数，不得预生成后续批次。
- 每组运行后写入：
  - `calibration_results.csv`
  - `calibration_log.txt`
  - 必要时更新 `best_params.json` 和 `best_run/`
  - `ai_analysis.md`

### C. 批内进度回报（必须）
- 至少在以下节点回报：第1次、第3-4次、第6次、第8次、第10次结束后。
- 回报格式参考：
  - `第52次已刷新全局最优：NSE=...。我继续跑完这批剩余9次。`
  - `进度到第54次，最优仍是第52次。我继续剩余7次。`

### D. 批次结束固定输出（必须）
- 输出以下四项：
1. 本批最优（Run、NSE、PBIAS、RMSE）
2. 当前全局最优是否刷新（是/否 + 运行号）
3. 该最优参数6元组
4. 下一批建议方向（1-2句）

### E. 继续机制（必须）
- 若 `AUTO_CONTINUE=true`，批次结束后自动进入下一批，不等待用户“继续下一批”。
- 若 `AUTO_CONTINUE=false`，批次结束后停住，等待用户指令。

---

## 禁止事项（新增）
- 禁止把“下一批参数生成”下放为脚本自动策略函数。
- 禁止省略批内进度回报，仅给最终结果。
- 禁止把批次执行改成“一次跑完整个max-runs”且中间不分析。

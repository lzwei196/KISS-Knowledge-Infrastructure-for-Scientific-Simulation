1 配置 Agent

目标： 先连接 AI，再开始科学项目。本 Windows 指南使用 DeepSeek API；第 3 页的真实示例也由这个接口完成。

连接 DeepSeek

  1. 打开 GeoForge Desktop，点击 设置 → AI 服务。
  2. 在 DeepSeek (API) 卡片上点击 获取密钥，在你自己的服务商账户里创建 API 密钥。返回 GeoForge，把密钥粘贴到卡片的密钥输入框。
  3. 选中 默认使用，点击 保存，再点击 测试 AI 与 GitHub。保存成功不等于连接成功。
  4. AI 测试通过后关闭设置。侧栏应显示 AI 就绪。若失败，先读测试错误，再检查服务商账户及 网络与代理 设置。

保护凭据。 API 密钥只填在设置中。不要把 API 密钥或 GeoForge 数据库 Token 发到聊天、截图或项目文件里。本例不需要 GeoForge 数据库。

新建项目

  1. 点击 ＋ 新建对话，命名为 SHAW official Trial。选择项目父文件夹，例如 D:\GeoForge\projects。Windows 浏览器模式下直接粘贴路径。
  2. 在第一条消息发出前，在对话顶部选择 API → DeepSeek (API) → deepseek-chat。
  3. 点击 自动选择 KI，搜索 SHAW，选中后点击 应用，然后继续第 2 页。

项目文件夹保存这个对话的输入、结果和运行记录。模型软件有独立的安装文件夹，可以被后续项目复用。

也可以使用本地 CLI

按 Claude Code 或 OpenAI Codex 等 CLI 自己的说明完成安装和登录。在 设置 → AI 服务 中点击 重新检查本地 CLI；在第一条消息前选择 本地 和对应 Agent。这是另一种连接方式；本指南的完整示例使用 DeepSeek API 验证。

检查点： AI 测试通过；新对话显示正确的 AI 和 SHAW。第一条消息发出后，要更换 AI 或 KI，请新建对话。

2 配置 KI 与模型软件

目标： 让真正的 SHAW 3.03 程序能在本机运行。KI 是模型的知识、说明和工具，不等于已经安装好的科学模型程序。

安装或验证软件

  1. 打开 KI 库，搜索并选择 SHAW。选择 DeepSeek (API)，点击 使用 Agent 设置。
  2. 在 Agent 设置 中保留 安装或编译新的副本。建议用简短、可写的路径，例如 D:\GeoForge\models\SHAW；修改后点击 使用此位置。
  3. 选择 deepseek-chat，点击 开始 Agent 设置。保持应用运行；下载和编译可能需要几分钟，留意 需要你 中的要求。
  4. 等 GeoForge 的最终验证。失败时先读 验证，再用 继续修复。Agent 说“安装好了”，或程序只打印了版本号，都不能证明安装通过。

已有 SHAW？选择 使用已经安装的软件，粘贴可执行文件路径，点击 使用此路径，再点击 验证已有软件。保留可执行文件所需的运行库 DLL。

若使用 GNU Fortran 编译，请让设置 Agent 核对同一编译器自带的 libgfortran-5.dll、libgcc_s_seh-1.dll、libwinpthread-1.dll、libquadmath-0.dll，以及 KI Python 环境中的 matplotlib。当前 KI 安装说明和预检包含这些依赖。

通过代表什么？ 软件能启动，所需环境可用。它还不证明某个科学算例正确运行。第 3 页将执行并核对真正的模型。

准备真实的 Trial 输入

下载 USDA-ARS 的 官方 Shaw303.zip，打开其中的 Shaw303/ 文件夹，提取这五个文件，不要把 Output/Trial/ 下的参考输出当作运行输入：

文件 用途
Trial.303.inp 原始控制选项与输出列表
Trial.30.sit 场地和土壤参数
Trial.30.wea 气象驱动
Trial.moi 初始含水量
Trial.tem 初始温度

回到 SHAW 对话，用 ＋ 文件 附上这五个文件。若审阅卡片要求提供某项输入，请用该输入行的 上传文件，把文件与计划关联。保留原文件名、内容和控制选项。

检查点： 软件验证通过，五个原始输入已准备好。安装可能需要协助：本次 Windows 验证曾修复缺失的编译器运行库。不能用自编公式、虚构驱动或现成输出替代模型运行。

3 批准运行并核对结果

目标： 用真实模型复现发布者的 SHAW Trial。这是官方示例的正向检验，不是利用实测观测进行校准。

发送这个请求

请用我上传的五个原始文件运行 SHAW 3.03 官方 Trial。保留全部科学输入和控制选项。将输入准备到本项目，用 KI 工具运行本机原生 SHAW，导出 CSV 并绘制土壤剖面。不用 GeoForge 数据库，不生成驱动，不校准参数。报告实际行数和时段；核对温度和含水量各 301 行、液态水 14 行、能量 300 行、水量 13 行、冻土 48 行，结束于 1986-12-17 00:00。

先审阅，再运行

  1. 逐一回答规划卡片，用卡片上的按钮保存选择。
  2. 在 Approve the plan?（是否批准计划）中检查：只用 SHAW；输入是五个真实文件；运行 → 解析 → 作图 均有可执行工具。确认输出位置，且没有提出校准。
  3. 不符合时选 Modify the plan（修改计划）；符合时选 Approve and start（批准并开始），再点击 Continue with this choice（按此选择继续）。只批准眼前这份具体计划。
  4. 保持应用运行。打开 ◇ 项目状态 查看配置、执行和检查。计划或工具发生变化时可能需要重新审阅，原批准不会自动涵盖变化。

已验证的示例结果

原始结果表 行数 核对内容

液态水 / 能量 14 / 300 完整参考时段

六张表均结束于 1986-12-17 00:00；初始温度和含水量剖面从 1986-12-04 12:00 开始。本次真实运行在输出的打印精度上与官方数值一致，另有五个 CSV 和真实绘图。

完成检查： GeoForge 必须显示 已完成，三个步骤都要有通过的运行记录。到 结果 打开 CSV 和图。AI 说成功、目录里有旧文件，或运行记录仍是警告/失败，都不等于完成。请 Agent 修复并重新运行受影响的已批准步骤，不要删除自己的输入。

需要校准时，打开 使用指南 → 参数校准指南；其他流程和排错看 完整使用手册。两个指南都能从同一菜单离线阅读。


## Deterministic native dependency build

The pinned PFLOTRAN v6.0 source requires PETSc 3.21.4 or later in `pflotran_constants.F90`; its `.gitlab/petsc-git-version.txt` pins v3.21.4. Use that exact compatible PETSc version instead of repeatedly guessing dependency combinations. The bundled `tools/build_pflotran_macos.py` downloads the SHA256-pinned official PETSc 3.21.4 archive, uses the genuine workspace Python 3.11 interpreter and native host MPICH, and builds parallel HDF5 1.14.3 with Fortran bindings once, upfront. Its options follow the pinned source's `.gitlab/build-petsc.sh` HDF5/Fortran configuration. This avoids retry 55's C-only HDF5 build followed by reconfiguration and recompilation.

The audited Homebrew HDF5 2.1.1 supplies genuine loadable Fortran libraries but is serial: its H5pubconf.h leaves `H5_HAVE_PARALLEL` undefined. It cannot supply the default parallel HDF5 Fortran calls simply by correcting library spelling. The dependency built through PETSc must retain `hdf5.mod` and `H5_HAVE_PARALLEL=1`; do not silently select PFLOTRAN's `SERIAL_HDF5` branches for this recipe.

PFLOTRAN's makefile expects `HDF5_INCLUDE` and `HDF5_LIB` to be bare directories. PETSc's generated variables contain compiler/linker flag strings. Pass the bare `<PETSC_DIR>/<PETSC_ARCH>/include` and `lib` paths explicitly as make command-line variables, with `have_hdf5=1`, to avoid malformed `-I-I` and `-L-L` arguments. Use the library names actually installed by the selected HDF5 version: Homebrew 2.1.1 and upstream 1.14.3 do not use identical primary high-level Fortran names.

Run the helper from the selected installation workspace after acquiring the exact clean source checkout. Invoke it using the genuine workspace Python 3.11 venv and actual KI helper path; source and dependencies remain inside that workspace. Host MPI needs the inherited verified `FI_PROVIDER=tcp` and `FI_TCP_IFACE=en0` on this Mac; other machines must use their real working interface. The resulting executable stays at `binaries/PFLOTRAN/source/repo/src/pflotran/pflotran`.

This minimal native configuration retains MPI and parallel Fortran HDF5. Optional Hypre preconditioners and METIS/ParMETIS partitioners are not included; their compile-time guards in the pinned source make that an explicit feature boundary, not proof that every scientific workflow is configured. No input deck, scientific dataset, or simulation is needed for installation-only startup checks. A local compile is not an independent DS installation pass.

Local native audit completed successfully: genuine Mach-O arm64 PFLOTRAN linked against PETSc 3.21.4, native MPI, BLAS/LAPACK, and the bundled parallel Fortran HDF5. `-help intro` exits 0 before input loading, as documented by PETSc's `pinit.c`; its introductory Fortran help prefix emitted several non-UTF8 bytes, retained in the audit's raw output. Ordinary `--version` is not implemented by PFLOTRAN and exits 87 after reporting only the missing scientific case `pflotran.in`. Do not add a dummy case to change that result. Full build receipts and raw startup evidence are retained separately; this local audit does not increment DS attempts.

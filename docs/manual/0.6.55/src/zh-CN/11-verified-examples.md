# 11 Windows 已验证示例与当前行为

前面的 FSM2 详细流程使用真实 0.6.54 界面，仍可用于学习完整工作流。本章补充 0.6.55 的验证，并给新用户一个简短、可复现的 SHAW 路径。

## 无需私人数据即可复现 SHAW

打开 **使用指南 → 快速上手 · 3 页**，依次完成 AI 设置、软件设置和已批准运行。官方下载地址是 [USDA-ARS Shaw303.zip](https://www.ars.usda.gov/ARSUserFiles/20520500/SHAW/303/Shaw303.zip)。五个原始文件直接位于压缩包的 `Shaw303/` 文件夹内：

`Trial.303.inp`、`Trial.30.sit`、`Trial.30.wea`、`Trial.moi`、`Trial.tem`。

把五个输入上传到新的 SHAW 对话。不要把 `Shaw303/Output/Trial/` 下的现成文件当成新的模型运行结果；那里是发布者提供的对照输出。输入与参考结果应分开保存。

要求通过 KI 执行真实原生模型、解析 CSV 并作图，保留全部原始控制选项。审阅并批准三个可执行步骤。完成后查看 **项目状态**、原始表、五个 CSV 和剖面图。模型的“软件验证通过”徽标本身不能证明科学运行完成。

## 实际核对了什么

| 模型 / 官方案例 | 已检查的真实输出 | 结果 |
|---|---|---|
| SHAW 3.03 / Trial | 温度 301 行、含水量 301、液态水 14、能量 300、水量 13、冻土 48；剖面 11 节点；均结束于 1986-12-17 00:00 | 打印精度上的数值与官方参考一致；检查了五个 CSV 和绘图；三个 Desktop 步骤均有通过的签名运行记录 |
| VIC 5.1.0 / Stehekin | 16 单元 × 十天，1949-01-01 至 1949-01-10；48 个通量、雪及雪带文件 | 原始驱动和参数不变；检查数值有限性和降水汇总；Desktop 已完成 |
| CRHM / Bad Lake | 8,760 个逐小时记录，1973-01-01 01:00 至 1974-01-01 00:00；三个 HRU 的 SWE | 原参数与驱动不变；结果匹配独立原生运行；Desktop 已完成 |

CRHM 三个 HRU 的峰值 SWE 分别为 36.38742、65.86527 和 64.42825 mm。原生程序报告版本 `4.7_16`；旧清单的 `1.3.5` 标签不能证明可执行文件的版本，本次另行记录了二进制身份。

这些是官方示例的正向运行，不是校准，也不是实测验证。安装曾需要协助：CRHM 首次配置受下载/构建问题阻碍，VIC 首个 Windows 构建在真实输入下崩溃，SHAW 需要修复运行库、依赖和路径。失败尝试均保留；后来的成功不会改写历史，也不保证所有电脑都能无人干预地安装。

## 与实际使用相关的修复

- **启动检查：** 不能只凭文件存在或打印出版本信息，就放过 Windows 加载/崩溃退出。预检使用配置的解释器和真实程序。
- **SHAW：** 检查受管理的软件路径、四个编译器 DLL 及 matplotlib。运行工具准备原始上传输入，保留 PEST/控制选项，授权重跑时回答原生程序的覆盖提示。所有启用的输出仍必须是新生成且完整的。
- **VIC：** 在最终 5.1.0 上复现并修复 Windows 配置光标、换行和错误报告问题；LF 与 CRLF 输入得到相同结果。“classic driver” 不再误选另一个 CLASSIC KI。
- **CRHM：** 只为模型子进程设置 `TZ=UTC0`，避免主机时区改变模型日历计算和 SWE。这不转换站点的地理时区；只移动旧输出的时间标签无法修复受影响的数值。
- **审阅：** 工具按所选项目的副本验证；未来的输出路径不再被说成现有输入。修改工具或计划可能使旧批准失效。
- **证据：** 明确命名的 stdout/stderr 日志仍被哈希记录，但不当作数值结果解析。真正的科学文件仍须通过数值和完整性检查。AI 的总结不能把失败、过期或没有记录的结果变成成功。

新的 SHAW 项目达到 **已完成**，三个步骤通过，没有缺失、过期、被拒的记录或无记录输出。早先未成功的对话已保留。如果你的项目积累了多次不相容的计划改动，可保留旧项目，用同一组真实输入建立新项目并重新审阅计划。

参数拟合及另行测试的原生 SHAW 参考恢复基准，见第 10 章或 **使用指南 → 参数校准指南**。

## 1. What this work was

Starting point: Codex thread `codex://threads/01a019c0-f9d9-7bb0-9549-09327b87f0d2` had left a large
uncommitted diff (catalogue search, capability bridge, KDT database KI). The user asked to review it,
fix the bugs, and then redesign how the GeoForge Database (GeoDB) is wired into planning. After that
we ran a real end-to-end VIC simulation through the app with DeepSeek and fixed everything it exposed.

User design decisions that are now hard rules in the code. Do not undo these:

1. **No plan auto-approval, ever.** Every plan waits for a click on the approval card.
2. **One-time Keychain prompt.** The DB token no longer lives in the login Keychain on macOS.
3. **Replanning happens in the same turn/window.** The agent has a `request_replan` tool; the CLI
   marker path triggers an automatic replan turn.
4. **Manual-delivery datasets (Baidu Pan, e.g. CMFD) are a normal option.** The agent learns them
   from the catalogue; the harness derives which DB records fit the study and tells the user.
5. **Project status shows what is and is not prepared.** Baidu link and extraction code live only in
   Project status; chat gets a reminder pointing there.
6. **Security:** activation token never printed, never given to agents; Baidu links and extraction
   codes never enter chat, logs, or agent context.

## 2. Architecture as it is now

### Catalogue store (app-level, not per project)
- Path: `~/Library/Application Support/KISS/database/catalogue.json` (0600, ~1 MB, ~1,100 records).
- Written by `obs_access.refresh_catalogue()`: pages `GET /api/obs/catalogue?offset&limit=500`,
  stores ETag, refreshes at app start and every 6 h (`CATALOGUE_STORE_TTL`), single background
  thread (`_REFRESH_LOCK`, non-blocking; readers use the last copy and see a "stale" flag).
- Triggered on: token save in Settings, app start (`gui.serve()` refresh loop), manual "Save & test".
- Readers: `obs_access.load_catalogue()`, `local_search()`, `search_catalogue()` (local first,
  server only if no local copy).
- Public fields exposed to agents: `CATALOGUE_PUBLIC_FIELDS` (id, name, delivery, size, format,
  bbox, point, start_date, end_date, variables, parent_id, notes, category, shape, ...).
  Anything matching `CATALOGUE_PRIVATE_FIELD_PARTS` (url, link, pwd, code, token...) is stripped
  by `public_dataset()`.

### Token
- `secret_store.py` on darwin: `_file_get/_file_set/_file_delete` under
  `~/Library/Application Support/KISS/secrets/<service>.<account>` (0600).
- `_mac_get_migrating()` reads Keychain once if the file is missing, writes the file, done.
  This was the last Keychain prompt the user saw.
- `obs_access.token_state()` returns `"set" | "missing" | "denied" | ...` without reading the token.
  `gui._database_status()` and `settings.masked()` use it, so status queries never touch secrets.

### Planning with the DB
- Intake and planning prompts receive a **study hint block**
  (`obs_access.study_hint_block(records, *texts)`): records matched from the goal text by
  station number (weight 4.0), basin/river names with CJK aliases (`_CJK_ALIASES`, e.g. 淮河 ->
  huai), keywords; broad aliases (`_BROAD_ALIASES`: china, tibet...) are down-weighted; records
  matching >3 % of the catalogue are dropped as noise. Injected in `flowrun.setup_turn()` and
  `flowrun.auto_turn()`; also `flowrun.database_hint_for(goal, mode)` for intake rules in gui.
- API agent tool `search_observation_data` (api.py) takes `q, bbox, start, end, variable,
  category, delivery`; description says manual delivery is a normal path.
- On `write_plan`, `obs_access.stamp_inventory(inventory, catalogue=...)`:
  resolves each inventory item to a catalogue id via `_pinned_id()` (dataset_id field, item id,
  `_fuzzy_id` on name), writes `dataset_id, name, delivery, size, format, bbox, point,
  start_date, end_date` (`STAMP_FIELDS`), returns validation errors for unknown ids, and
  **refuses whole-product parents** (a record with children, e.g. `cmfd_china_daily_010`) as
  download units. Child ids follow `CHILD_ID` = `parent__variable_YYYY` and download via
  `/child/{id}/download`.
- Served downloads: cap `MAX_SERVED_BYTES` = 100 MB (server limit). Above that or `delivery:
  manual` -> `manual_handoff_message(info)` -> setup request (kind `download`) with url,
  extraction code, `expected_path`. Only Desktop reads the `/download` handoff.

### Flow states (ki_tools_common/flow)
RESOLVING_KIS -> PLANNING/REPLAN_REQUIRED -> WAITING_FOR_USER -> APPROVED -> EXECUTING ->
VERIFYING/COMPLETED/FAILED_VALIDATION. Transitions used from Desktop: `replan`, `rerun`, `drift`.
Receipts: `.geoforge/receipts/model-runs/*.json`, `.geoforge/receipts/data-receipts/*.json`.
Approval: `runs/approval.json` with plan/inventory/tool sha256; revoked copies kept as
`approval.revoked.<ts>.json` + `.reason.txt`.

| Symptom | Root cause | Fix |

| Plan ran without a click after modify/replan | auto-approval when no pending options | removed entirely |
| Card said "Not ready" for run-generated intermediates | validator counted outputs of earlier steps as missing inputs | `for_execution` skips them |
| Session stuck in FAILED_VALIDATION | no transition out | `rerun` on next user message |
| Downloads invalidated after replan | receipts bound to plan hash | `_download_still_valid` |
| Keychain prompt every build | ACL bound to ad-hoc signature | private 0600 file store, one migration |
| Documents TCC prompt every build | session listing opened external folders | `external: True` pointer, no open |
| "TypeError: Load failed" at startup | backend blocked by a system prompt during first fetch | boot retry loop + Reload |
| Agent asked to "move back to PLANNING" | no same-turn path | `request_replan` tool + auto replan turn |
| Agent claimed S1–S4 done, 0 tool calls | nothing corrected it | verification line "receipt: 0 of N" |

## 9. Gotchas for whoever picks this up

- `kiss/tests/conftest.py` redirects the catalogue store and secret store; if a test writes to
  `~/Library/Application Support/KISS`, the fixture is not applied.
- Approval helpers in tests: `_approve` / `_click_approve` (there is no auto path anymore).
- `write_plan` may arrive in two tool calls; check `flow.pending_plan_parts` when debugging.
- A step's `tool` must be a KI tool path **or** a binary declared in
  `knowledge_infrastructure.yaml`; anything else fails plan validation.
- Study hints: station numbers dominate matching; if a hint block looks empty for a Chinese goal,
  check `_CJK_ALIASES` for the basin name.
- zsh scripts that glob receipts need `setopt nullglob`.

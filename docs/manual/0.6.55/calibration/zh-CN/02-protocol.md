# 制定有依据的校准方案

## 引擎、适配器与案例

| 部分 | 负责什么 | 位置 |
|---|---|---|
| 统一引擎 | 执行优化算法并检查留出结果 | 随 GeoForge 提供 |
| KI 适配器 | 写入参数、启动原生模型、读取真实输出并返回评分 | 项目的 `calibration/kis/<KI>/` |
| 项目案例 | 定义参数、目标、时段、指标和预算 | `calibration/cases/` |
| 运行证据 | 记录请求、日志、评分、参数和接受结论 | `calibration/runs/<run id>/` |

KI 附带的适配器是起点，不代表它已经适合你的流域、变量或观测格式。没有适配器时，由 Agent 在项目中准备适配器，统一优化引擎保持不变。经过测试的 SHAW 示例采用这种方式。

## 搜索方法

| 目标 | 支持的方法 | 怎样选择 |
|---|---|---|
| 单个标量损失 | DDS、SCE-UA、DREAM | 明确损失的方向和单位，记录种子与预算。 |
| 多个相互竞争的目标 | NSGA-II、NSGA-III、MOEA/D | 比较候选解之间的取舍，不要用未说明的平均分掩盖差异。 |

算法名称不保证收敛。参数越多、越难辨识，需要的依据和计算通常越多。应用接受 1 至 10,000 的优化器请求预算。它不是原生模型调用次数的严格上限：优化器初始化或整批种群计算，以及基线、留出检查，都可能增加工作量。核对实际评估次数，并计入每次原生运行的成本。先做小预算通路测试，再批准大预算。

## 批准前逐项核对

- **目标与对齐：** 变量、单位、时间支撑尺度和空间范围一致。点观测不能自动验证流域平均值。
- **参数范围：** 来自模型文档、测量或文献；互相关联的参数要一致。不能仅因为某参数能移动结果，就把它设为可调。
- **驱动数据：** 不要为掩盖模型与数据的不一致，随意调低降水、改变高程或改写观测转换。
- **时段划分：** 优化看不到留出时段。评分前的暖启动时段可以保留，但要明确记录。
- **指标：** 指定决定是否接受的指标及诊断指标，报告基线、拟合结果、样本数和缺测处理。
- **可复现性：** 保留可执行文件版本/哈希、原始输入、实际写入的参数、种子、预算及评分代码。

摄氏温度的零点是人为定义的，百分比偏差不适合直接用于这种温度。因此 SHAW 参考测试报告 NSE 和 RMSE，不报告摄氏温度 PBIAS。其他变量应按该模型的验证规范选择指标，不能机械照搬。

训练分数改善而留出表现变差，提示过拟合或方案存在问题。不能再把留出数据加进训练，却继续把同一留出成绩说成独立检验。

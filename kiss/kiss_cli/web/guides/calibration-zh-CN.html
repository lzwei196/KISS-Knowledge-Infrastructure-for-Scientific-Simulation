校准真实模型

校准是搜索一组参数，让模型更接近指定目标。GeoForge 提供统一的搜索引擎；KI 适配器负责把参数写入真实模型、运行模型、读取输出并评分。优化引擎不能替代科学模型本身。

区分三个结论。 引擎能工作、校准运行成功、模型经过独立实测验证，是不同的事。本指南的 SHAW 测试恢复的是发布者参考输出对应的参数，不是野外观测验证。

准备项目

  1. 先用目标输入完成一次未校准的模型运行，检查日期、单位、水量或能量平衡和物理合理性，再考虑优化。
  2. 若原项目已经 已完成，新建对话。在第一条消息前选好 KI 和 AI。
  3. 提供真实观测及时间戳、单位、位置、缺测处理规则，明确每个观测变量对应哪项模拟输出。
  4. 给出参数名称、含义、单位、有依据的范围、固定参数、拟合时段，以及独立的留出时段。优化搜索不能使用留出数据。
  5. 约定算法、运行预算和随机种子，要求同时报告基线与拟合参数在两个时段的结果。

用你自己的观测提出请求

请针对我将上传的观测文件校准所选模型。先检查基线及时间、空间和单位对齐。提出少量具有物理依据的参数及范围；除非有独立依据，不要改动驱动或观测修正。只在约定的训练时段拟合，把后续时段留作检验。使用 DDS，预算 100 次评估，并记录随机种子。报告基线和拟合参数在两个时段的指标、失败评估及准确的模型和输入版本。运行前先给我审阅计划。

日期、范围和指标是你这个研究的科学决定，不能直接从这段示范文字推定。回答规划卡片，并通过输入行的 上传文件 关联所需观测。

先准备适配器，不执行校准

如果所选 KI 缺少项目适配器，规划阶段只能在该 KI 的项目校准目录中编写校准约定和运行脚本这两个文件，供审阅。这不授权启动优化、执行原生模型或任意修改项目文件。

审阅并运行

  1. 在 ◇ 项目状态 → 更多细节 → 校准 查看适配器和项目案例是否齐备。需要适配器 代表准备工作未完成，不是引擎坏了。
  2. 让 Agent 校准（后续为 继续校准）会向对话发送请求；添加观测数据 用于附加文件。计划里必需的输入仍要通过对应上传行关联。
  3. 在 Approve the plan? 上检查输入、参数范围和默认值、目标、训练/留出划分、算法、请求预算、种子及可执行校准步骤。计划会绑定将要执行的确切适配器与校准约定。不符合研究要求就修改计划。
  4. 选择 Approve and start，再点击 Continue with this choice。GeoForge 为已批准的执行留存运行记录，AI 的文字承诺不能替代记录。
  5. 保持应用运行。停止 会结束当前尝试并保留其结果记录。停止或失败的尝试不能当成成功拟合。

批准之后改变适配器、约定、数据、参数范围或调用方式，需要重新审阅相关计划。API Agent 和本地 CLI Agent 都必须使用已批准的校准步骤并记录运行；切换 Agent 类型不能绕过批准。不要在优化运行中改写它正在使用的文件。

制定有依据的校准方案

引擎、适配器与案例

部分 负责什么 位置
统一引擎 执行优化算法并检查留出结果 随 GeoForge 提供
KI 适配器 写入参数、启动原生模型、读取真实输出并返回评分 项目的 calibration/kis/<KI>/
项目案例 定义参数、目标、时段、指标和预算 calibration/cases/
运行证据 记录请求、日志、评分、参数和接受结论 calibration/runs/<run id>/

KI 附带的适配器是起点，不代表它已经适合你的流域、变量或观测格式。没有适配器时，由 Agent 在项目中准备适配器，统一优化引擎保持不变。经过测试的 SHAW 示例采用这种方式。

搜索方法

目标 支持的方法 怎样选择
单个标量损失 DDS、SCE-UA、DREAM 明确损失的方向和单位，记录种子与预算。
多个相互竞争的目标 NSGA-II、NSGA-III、MOEA/D 比较候选解之间的取舍，不要用未说明的平均分掩盖差异。

算法名称不保证收敛。参数越多、越难辨识，需要的依据和计算通常越多。应用接受 1 至 10,000 的优化器请求预算。它不是原生模型调用次数的严格上限：优化器初始化或整批种群计算，以及基线、留出检查，都可能增加工作量。核对实际评估次数，并计入每次原生运行的成本。先做小预算通路测试，再批准大预算。

批准前逐项核对

  • 目标与对齐： 变量、单位、时间支撑尺度和空间范围一致。点观测不能自动验证流域平均值。
  • 参数范围： 来自模型文档、测量或文献；互相关联的参数要一致。不能仅因为某参数能移动结果，就把它设为可调。
  • 驱动数据： 不要为掩盖模型与数据的不一致，随意调低降水、改变高程或改写观测转换。
  • 时段划分： 优化看不到留出时段。评分前的暖启动时段可以保留，但要明确记录。
  • 指标： 指定决定是否接受的指标及诊断指标，报告基线、拟合结果、样本数和缺测处理。
  • 可复现性： 保留可执行文件版本/哈希、原始输入、实际写入的参数、种子、预算及评分代码。

摄氏温度的零点是人为定义的，百分比偏差不适合直接用于这种温度。因此 SHAW 参考测试报告 NSE 和 RMSE，不报告摄氏温度 PBIAS。其他变量应按该模型的验证规范选择指标，不能机械照搬。

训练分数改善而留出表现变差，提示过拟合或方案存在问题。不能再把留出数据加进训练，却继续把同一留出成绩说成独立检验。

阅读结果并保留证据

理解校准卡片

状态 含义和下一步
Engine unavailable（引擎不可用） 随应用提供的引擎无法加载，先修复安装。
Adapter needed（需要适配器） 所选 KI 尚需项目适配器。
Project case needed（需要项目案例） 补全目标、参数范围、观测与留出时段。
Workflow prepared（工作流已准备） 案例已保存，但仍要检查是否符合本研究。
Holdout passed（留出检验通过） 满足已配置的留出检查；仍要阅读报告和科学限制。
Holdout not passed（留出检验未通过） 不应把拟合参数提升为已验证结果；检查方案或模型与数据差异。
Run needs review（运行需要检查） 查看失败或中断的尝试与日志。

最新校准上的 Validated（已验证）只表示通过已配置的检查。它不证明全部物理过程正确、参数唯一，或模型在其他地点也有效。Not promoted（未采用）表示工作流没有接受这次拟合供后续使用。

打开结果文件

通过项目文件、结果面板或磁盘上的项目文件夹，查看 calibration/runs/<run id>/：

  • report.json：宿主的结果和接受结论。
  • engine-report.json：优化过程及留出检验详情。
  • engine-request.json：实际交给引擎的案例和方案。
  • engine.log：执行和诊断日志。

每次运行单独保存不可被后续运行覆盖的校准运行时副本，以保留当时的执行依据。同时保留项目适配器、案例、原始观测及模型输入。每次评估的文件应能核对哪些值真正写进了模型。进程成功退出，但没有可读的科学输出，不是有效评估。

判断拟合是否可用

  1. 确认运行了真实模型，所有报告的参数都实际应用了。核对命令、可执行文件身份、生成的参数与输入文件。
  2. 在训练和留出两个时段比较基线与拟合指标，检查样本数及日期。
  3. 查看时间序列和残差，不只看一个总分。核对 KI 要求的物理约束和平衡。
  4. 报告不确定性、参数可辨识性的限制，以及贴近边界的参数。一个最优点并不代表不确定性已经得到量化。
  5. 检查运行记录和最终项目状态。必需的留出检查缺失或被拒绝时，结果为警告，不能算科学工作已完成。AI 的总结不能覆盖失败验证、已变化的输入或缺失证据。

使用 GeoForge 的 停止 中断优化。Windows 启动非交互校准子进程时不会请求控制台窗口；模型自身的图形交互行为仍需单独验证。

运行失败时保留报告和错误文字，解决真实原因，再获得一次新的成功运行。不要把失败报告改名当成功，更不能用参考输出替代模型执行。

已测试示例：恢复 SHAW 参考参数

真实结果

拟合倍率为 1.003065603。训练 NSE 为 0.99998413，RMSE 为 0.011098 °C。留出 NSE 从扰动基线的 0.98713640 提高到 0.99998794。已配置的留出检查通过，引擎在本基准范围内将结果标记为可采用。

统一引擎固定在修订 579162102f71f2fa4619b874a21bd219caaed25e。适配器属于项目，位于 calibration/kis/SHAW/calibration.yaml 和 tools/calib_run.py，并不因此宣称有适用于所有 SHAW 研究的通用适配器。完整证据保存在测试项目及验证机器上的 D:/GeoForge-Calibration-20261002/native-calibration-result.json。

源码与打包后的 Windows 引擎得到相同拟合结果。包含探测、基线和留出检查在内，测试实际调用原生模型 64 次。另一次已知参数值 1.0 的运行与发布者的温度输出逐字节一致。六种优化算法也都通过了合成函数接口测试；这些合成测试不能证明科学预测能力。

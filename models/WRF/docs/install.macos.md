# WRF 4.7.1 native Mac build repair

Use the official source commit `f52c197ed39d12e087d02c50f412d90d418f6186`. The previous native build compiled its external libraries but registry code generation stopped with SIGTRAP and an empty registry log. This is not evidence that ARM64 cannot run WRF's registry.

The pinned `tools/reg_parse.c` stores complete include paths in 128-byte arrays and fills them with unchecked sprintf calls. A normal long installation root exceeds those buffers. Native GCC with fortification reproduced SIGTRAP (-5), empty output, in 0.04 seconds with a 216-byte include path. The bundled `tools/prepare_wrf_build_registry.py` verifies the exact original source hash, enlarges only those path buffers to 4096 bytes, uses checked snprintf, and refuses paths that still exceed them. The identical regression then completed native code generation in 5.45 seconds, producing real `frame/module_state_description.F` (88,728 bytes) and `inc/nl_config.inc` (1,250,189 bytes). No scientific source or model calculation changes.

From the selected installation workspace, run the helper at its actual KI path with `--source binaries/WRF/source/repo` before building registry. It is idempotent and refuses unrecognized source content or a target outside that workspace. Rebuild registry after applying it. Keep compiler fortification enabled.

Registry generation must receive the actual ARW definitions, including `-DEM_CORE=1 -DDA_CORE=0 -DNEW_BDYS`. Omitting DA_CORE=0 in an isolated debug invocation removes j/k dimension declarations and triggers a separate upstream loop printing missing-tracer warnings. Compile registry with MAX_HISTORY matching the full build (25 in the audited configuration). An earlier ASAN debug executable also hung before main inside sanitizer/dyld initialization; that was a debugging-runtime failure, not WRF generation.

Source `main/CMakeLists.txt` declares these native executable targets without an executable suffix; a build directory named `build` yields `build/main/wrf` and `build/main/real`. Installation also creates `.exe` links in its run directory. Traditional WRF make can produce `main/wrf.exe`; verify whichever actual native product the chosen build creates. Never select the registry generator, wrappers, or KI preflight as WRF itself.

The previous Darwin toolchain importer also left bare MACOS tokens in compiler flag strings; preserve `-DMACOS` as a definition and validate the imported flags.

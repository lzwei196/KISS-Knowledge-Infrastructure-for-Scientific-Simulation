# Stage 5: Execution

## Purpose

Compile the GeoClaw Fortran solver and run the simulation.  GeoClaw uses a
Makefile-based build system that compiles Fortran source files from the
clawpack library together with any user-provided custom routines (e.g.,
`qinit.f90` for initial conditions).  The resulting executable (`xgeoclaw`)
reads `.data` files and produces output in the `_output/` directory.

## Prerequisites

- Stage 3 (configuration) completed — setrun.py and .data files exist
- Topography and dtopo files in place
- Fortran compiler installed (gfortran recommended)
- CLAW environment variable set to clawpack root
- Sufficient disk space for output (can be large with fine AMR)

## Inputs

| Input | Format | Notes |
|-------|--------|-------|
| `setrun.py` | Python | Configuration script |
| `Makefile` | Makefile | Build instructions |
| `*.data` files | Fortran data | Generated by `python setrun.py` |
| Topo files | Type 1–4 | Referenced in `topo.data` |
| dtopo files | Type 1–4 | Referenced in `dtopo.data` |
| Custom Fortran | `.f90` | Optional: qinit.f90, src2.f90, etc. |

## Outputs

| Output | Location | Description |
|--------|----------|-------------|
| `xgeoclaw` | run directory | Compiled executable |
| `fort.qNNNN` | `_output/` | Solution at each output frame |
| `fort.tNNNN` | `_output/` | Frame metadata (time, grid count) |
| `fort.aNNNN` | `_output/` | Auxiliary variables (bathymetry) |
| `fort.gauge` | `_output/` | Gauge time series |
| `fgmaxNNNN.txt` | `_output/` | Maximum value grids (if configured) |

## Procedure

1. **Set environment variables:**
   ```bash
   export CLAW=/path/to/clawpack
   export FC=gfortran
   ```

2. **Generate data files:**
   ```bash
   python setrun.py
   ```

3. **Compile and run (via Makefile):**
   ```bash
   make .exe     # Compile only
   make .output  # Run simulation
   # OR
   make all      # Compile, run, and plot
   ```

4. **Alternative: Direct execution (without Makefile):**
   ```bash
   python ki/tools/run_geoclaw.py \
     --run-dir /path/to/example \
     --use-makefile \
     --timeout 7200 \
     --json-output run_result.json
   ```

5. **Monitor progress.**  GeoClaw prints progress to stdout:
   ```
   GEOCLAW: Frame    1 output files done at time t = 900.0000
   GEOCLAW: Frame    2 output files done at time t = 1800.0000
   ```

6. **Check for errors.**  Common failure modes:
   - `*** Error: CFL too large` — reduce `cfl_desired` or increase resolution
   - `forrtl: severe (174)` — Fortran runtime error, check data file format
   - Memory exhaustion — reduce AMR levels or domain size

## Verification

- [ ] Compilation completes without errors
- [ ] Executable `xgeoclaw` is created
- [ ] `_output/` directory is created with fort.q files
- [ ] Multiple fort.q files exist (not just fort.q0000)
- [ ] No NaN or Inf in the final fort.q file
- [ ] Gauge file exists (if gauges were configured)
- [ ] Runtime is reasonable (seconds for test cases, hours for real applications)

## Traps

| Trap | Triplet | Impact |
|------|---------|--------|
| CFL exceeds 1.0 during run | dt_011 | Simulation aborts or produces NaN |
| Missing topo file at runtime | dt_014 | Zero bathymetry in uncovered regions |
| Fortran compiler not found | dt_017 | Cannot compile |
| CLAW not set | dt_018 | Cannot find source files |
| Output too large for disk | dt_015 | Simulation hangs or crashes |
| Memory overflow from too many AMR levels | dt_013 | OOM kill |

## Example

Running the bowl-slosh test case:

```bash
cd $CLAW/geoclaw/examples/tsunami/bowl-slosh

# Generate topography
python maketopo.py

# Compile and run
make new    # Clean compile and run

# Check output
ls _output/fort.q*
# Expected: fort.q0000 through fort.q0010 (11 frames)

# View gauge data
head -20 _output/fort.gauge
```

Typical runtime for bowl-slosh: ~10–30 seconds on a modern CPU.
